# OMP Switch v0.4.1

This release deepens the desktop app's interaction and visual finish across the surfaces that still
read as utilitarian. The usage dashboard, session viewer, YAML preview, diagnostics, empty states,
left rail, provider cards, forms, snapshot timeline, and roles resolution chain all move closer to
the "Quiet Instrument" goal — premium and restrained, not because of color, but because of
hierarchy, spacing, and consistent control language. No new IPC channels; no new dependencies.

## Added

- **Usage dashboard**: expandable rows expose the full token split (input/output/cacheRead/cacheWrite/
  reasoning), cache hit rate, and a per-model daily cost sparkline. The trend chart is now an SVG
  area chart with a cost/requests/tokens dimension switcher and a Radix tooltip card. The top KPI
  area collapsed from five flat cards into three composite cards (cost + source + a token-composition
  stacked bar; requests + failure rate; cache hit). A new `UsageReport.byModelByDay` and
  `byProviderByDay` feed the in-row sparklines.
- **Session bubbles**: messages render as role-aware chat bubbles instead of a raw text block — user
  turns right-aligned with ink/paper inversion, assistant turns left-aligned sunken blocks carrying
  the model, system/tool/result turns as centered quiet strips. Code fences and whitespace survive.
- **YAML preview**: models.yml and config.yml get separate file tabs, line numbers, and a hand-written
  four-color syntax highlighter (key/string/number/comment), replacing the single merged `<pre>`.
- **Diagnostics summary**: a status LED plus error/warning/info counts at the top, with items grouped
  by severity (errors first).
- **Empty states**: soft rounded panels with a large tinted glyph, a context line, and a primary/
  secondary CTA pair, replacing the dashed-border placeholder across all modules.

## Changed

- **Left rail**: the seven modules are grouped into 配置 / 内容 / 运维 with section titles; the active
  state moved from a 3px accent rail to a soft rounded fill block with a signal-tinted icon.
- **Provider card header**: primary/secondary split — the header row keeps only the name, api, a
  model-count badge, and the chevron; endpoint, key status, and coverage moved into a sunken meta bar
  above the model list.
- **Provider edit form**: grouped into 身份 / 连接 / 模型 / 高级 cards with hint lines, including the
  note that OMP reads keys via `!command` and never writes them to config.
- **Snapshot timeline**: drawn as a vertical-line timeline with node dots and inline restore buttons,
  instead of a flat clickable list.
- **Roles resolution chain**: split into a secondary quiet reference chain and a primary resolved-model
  line, so the final model reads at a glance.

## Security

- No new IPC channels. The usage rework extends the existing `omp:usage-summary` payload with
  `byModelByDay` / `byProviderByDay` only. The YAML highlighter runs renderer-side on text already
  loaded by the existing config-read path, with no new filesystem or network access.

## Feature status

- **Gateway**: experimental, headless only (`--gateway [profile]`), loopback with a mandatory
  bearer token; unchanged in this release.
- **OAuth integration**: passthrough to `omp auth status` / `omp auth login` only; no token
  storage or refresh handling in-app; unchanged.
- **Session indexing**: always on — two-phase incremental refresh backed by the on-disk metadata
  cache; unchanged. The session viewer's new bubbles read the same indexed messages.
- **Update checking**: not implemented; no update manifest is published with this release.

## Known limitations

- The desktop application is Windows-only because its credential path uses Windows DPAPI.
- The binaries are not code-signed, so SmartScreen can warn on first run.
- Mica requires Windows 11 22H2+ and falls back to solid surfaces elsewhere; the custom title bar
  requires Windows 10+ and falls back to the system frame elsewhere.
- winget and Chocolatey submissions remain pending in their external review queues.
