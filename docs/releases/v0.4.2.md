# OMP Switch v0.4.2

This release is a visual and interaction polish pass across the surfaces that still read as
utilitarian after v0.4.1 — the command palette, session viewer, snapshot timeline, diagnostics,
and the card/border language that ties the whole app together. No new IPC channels and no new
dependencies; every change is renderer-side CSS and React.

## Changed

- **Command palette (Ctrl+K)**: rewritten to an icon-prefixed list in the OpenAI/Linear register.
  Each item carries a leading glyph (shared with the left-rail icon language, so a search hit reads
  as the same destination), a label, and a `↵` affordance that lights up on the selected row. The
  input gained a leading search glyph; Profile items show 当前 / ↵ and provider items show a
  model-count chip. Group headings tightened.
- **Session detail**: the "load earlier messages" control moved inside the scroll area at the top,
  so the pagination entry stays visible instead of being pushed below the thread. The selected
  session row now carries a 3px signal left rail so the active row and the detail panel feel
  connected rather than just same-colored.
- **Snapshot timeline**: the latest snapshot reads as the current state — a filled signal node with
  a soft ring, plus a 最近 badge — instead of every snapshot reading as equal weight.
- **Diagnostics**: rows widened (padding 11px / gap 10px) and severity groups separated by a margin
  so the title-to-list hierarchy is clearer.
- **Card language**: provider cards, role cards, module list/editor panels, usage cards, the trend
  wrap, the pricing editor, and empty states gained a 1px hairline border in addition to their
  shadow, so panels separate by tone plus a hair rather than only by shadow — closer to the Apple
  Settings register. The light-mode hairline lifted toward a cooler, lower-contrast neutral; the
  dark-mode hairline sits barely above the panel.
- **Usage trend**: gradient stops carry per-theme opacity via CSS classes (dark mode nudged up) so
  the area fill reads on dark panels instead of fading into them; the trend line stroke widened to
  1.75.
- **Display headings**: a new `--fs-display` (28px) token drives module page titles — the single
  largest type on the page, reserved for titles — with tighter tracking.
- **Dark-mode signal** desaturated from `#43b8aa` to `#3fb6a6` (teal-mint) so it reads as a
  highlight rather than a saturated accent; dark-mode trend colors lifted to a clearer mint.
- **Profile drawer**: now tabbed (设置 / 项目 / 快照 / OMP / OAuth) with a sticky tab bar, so its five
  concerns no longer scroll as one long stack.
- **Provider edit form**: de-duplicated its `input/select/textarea` styling — the field rules now
  live in one place with a single override for fields inside a sunken form-group, removing a stale
  duplicate block that had drifted out of sync.
- **Quick-assign affordance**: the per-row model-to-role assign button is now faintly present at
  rest (opacity 0.4) so it is discoverable without hovering, intensifying on hover/focus; touch
  users (no hover) still see it.

## Security

- No new IPC channels and no new dependencies. All changes are renderer-side CSS and React; the
  usage trend, session message, and YAML paths are unchanged. No filesystem, network, or secret
  surface was touched.

## Feature status

- **Gateway**: experimental, headless only (`--gateway [profile]`), loopback with a mandatory
  bearer token; unchanged in this release.
- **OAuth integration**: passthrough to `omp auth status` / `omp auth login` only; no token
  storage or refresh handling in-app; unchanged.
- **Session indexing**: always on — two-phase incremental refresh backed by the on-disk metadata
  cache; unchanged. The session viewer's revised bubbles read the same indexed messages.
- **Update checking**: not implemented; no update manifest is published with this release.

## Known limitations

- The desktop application is Windows-only because its credential path uses Windows DPAPI.
- The binaries are not code-signed, so SmartScreen can warn on first run.
- Mica requires Windows 11 22H2+ and falls back to solid surfaces elsewhere; the custom title bar
  requires Windows 10+ and falls back to the system frame elsewhere.
- winget and Chocolatey submissions remain pending in their external review queues.
