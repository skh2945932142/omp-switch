# OMP Switch v0.4.3

This release aligns OMP Switch with Oh My Pi v17.4.0–v17.4.2. OMP added new writable `models.yml`
and `config.yml` fields across three upstream versions, and one of them — the nested `cost.longContext`
object subscription Codex GPT-5.6 models carry — was a hard write blocker: OMP Switch's own validator
rejected a file OMP had written, so the commit was refused and the user could not save any change.
That blocker is fixed, and the new fields are now first-class in the schema, the validator, the YAML
writer, and the UI.

No new IPC channels and no new dependencies. Every change is in the config-write path or the
renderer form.

## Fixed

- **`cost.longContext` no longer blocks a commit.** `validation.ts` treated any non-number value
  inside a provider or model `cost` mapping as an error. OMP v17.4.0+ writes a nested
  `cost.longContext` tier object on subscription Codex GPT-5.6 models (`{ "272000": 2.5, ... }`),
  so OMP Switch refused to commit any change to a config that carried one — even though OMP itself
  had written the file. The check now accepts a finite non-negative number **or** a mapping whose
  own values satisfy the same rule (recursive), and only rejects genuinely malformed values
  (non-finite, negative, structurally wrong). This was the only change that could stop a save
  outright, so it is the headline fix.

## Added

- **`models.yml` fields** (OMP v17.4.0+):
  - `tokenizer` — a model-level (and `modelOverrides`) family string (`claude-v3`, `claude-v47`,
    `claude-v5`, `claude-v5-sonnet`, `qwen3`, `deepseek-v3`, `kimi-k2`, `glm5`) that pins the
    embedded local tokenizer for proxy models with an ambiguous id. An unknown family is a warning,
    not an error — matching how `api` is treated, since OMP may add families.
  - `compat.qwenTemplateReasoningEffort` — accepted as part of the existing `compat` mapping.
  - `cost.longContext` — accepted by the validator (see Fixed).
  - `providers.<id>.codeMode` — the `off`/`auto`/`on` enum (documented for `openai-codex`) is now
    writable from the provider's Advanced section.

- **`config.yml` settings** (OMP v17.4.0–v17.4.2), all editable from the Profile drawer's new
  **行为 (Behavior)** section:
  - `compaction` — the full mapping (`methodOrder`, `asyncEnabled`, `enabled`, `midTurnEnabled`,
    `thresholdPercent`, `thresholdTokens`, `reserveTokens`, `keepRecentTokens`, `autoContinue`).
    `methodOrder` is the ordered fallback list that replaced the deprecated `strategy`/
    `remoteEnabled`; those deprecated keys are still read without error so files an older OMP wrote
    are not flagged.
  - `extendedContext` — whether models with premium long-context pricing tiers use the extended window.
  - `externalThinking` — surfaces external thinking as a `/settings` row carrying a risk note.
  - `personality` — `default`/`friendly`/`pragmatic`/`none`; a user-level
    `<agent dir>/PERSONALITY.md` replaces the preset's text, `none` omits the block.
  - `images.urls.enabled` — the opt-in image URL broker (tri-state: unset / on / off) that publishes
    outgoing images as URLs instead of inline base64 for URL-fetching providers.

## Changed

- **`compaction` and `images` are now patched child-by-child, not replaced whole.** The YAML writer
  diffs these mappings per sub-key (the same `patchMap` path `modelRoles` and each provider entry
  use), so a user's comments and sibling sub-keys this app does not write — e.g. an OMP-added
  compaction tuning key, or `images.autoResize` — survive an edit to `methodOrder` or
  `images.urls.enabled`. An array inside (`compaction.methodOrder`) is still replaced wholesale,
  which is correct for an ordered list. Scalar and array settings keys
  (`modelProviderOrder`, `enabledModels`, `disabledProviders`, `defaultThinkingLevel`,
  `extendedContext`, `externalThinking`, `personality`) keep their whole-node replacement, since
  they have no per-element identity to preserve.

- **`SettingsDocument.images` widened** to an open shape (`{ urls?: { enabled?: boolean };
  [key: string]: unknown }`) so fields OMP carries that this app does not edit round-trip through
  the writer.

- The Profile drawer's **设置 (Settings)** tab is now split into two sections — 选择 (Selection:
  provider order, enabled models, disabled providers, default thinking) and 行为 (Behavior:
  personality, extended/external thinking, image URL mirroring, compaction) — each with its own
  dirty indicator. The single 保存设置 button saves both.

## Security

- No new IPC channels and no new dependencies. All changes are in the config-write path
  (`packages/core`) and the renderer form. The secret vault, the loopback gateway, and the
  snapshot/hash-guard write path are unchanged. No filesystem, network, or secret surface was
  touched. `apiKey` continues to be enforced out of OMP config by validation
  (`provider.apiKey-plaintext`), not by the UI.

## Feature status

- **Gateway**: experimental, headless only (`--gateway [profile]`), loopback with a mandatory
  bearer token; unchanged in this release.
- **OAuth integration**: passthrough to `omp auth status` / `omp auth login` only; no token storage
  or refresh handling in-app; unchanged.
- **Session indexing**: always on — two-phase incremental refresh backed by the on-disk metadata
  cache; unchanged.
- **Update checking**: not implemented; no update manifest is published with this release.

## Known limitations

- The desktop application is Windows-only because its credential path uses Windows DPAPI.
- The binaries are not code-signed, so SmartScreen can warn on first run.
- Mica requires Windows 11 22H2+ and falls back to solid surfaces elsewhere; the custom title bar
  requires Windows 10+ and falls back to the system frame elsewhere.
- winget and Chocolatey submissions remain pending in their external review queues.
- **Usage cross-checking with `cost.longContext` is not yet supported.** The usage dashboard's
  `recordedCost` (what OMP recorded per turn) is authoritative and unaffected, but the local
  `computedCost` cross-check still prices only the four scalar `cost` fields and ignores the
  long-context tier pricing, so a long-context request on a tiered model will show a `computedCost`
  lower than the recorded one. Tiered pricing will land in a follow-up once the `longContext` object
  shape is confirmed against real files.
