# OMP Switch v1.0.1

A patch release that unblocks saving for configurations whose role selectors point at providers `models.yml` does not list.

## Fixed

- **Role selectors naming an undeclared provider no longer fail validation.** OMP resolves role and fallback-chain selectors against every provider it has registered, including built-ins such as `web`, OAuth CLI providers, and extension providers registered at runtime through `pi.registerProvider`. Only providers declared in `models.yml` were accepted, so a config using `web/firecrawl` or a `retry.fallbackChains.web` list was rejected with `Invalid selector for role …` and `Chain "web" must be a non-empty array …`. `previewPatch` throws on load-time errors, so this blocked every save in the app.
- **Non-ASCII provider ids resolve.** Provider ids are YAML keys OMP accepts verbatim; the ASCII-only token check dropped names such as `小水管`, which made every role pointing at them look invalid.
- **Undeclared providers are reported as warnings.** The role, fallback-chain, and `compactionModel` checks now surface them without refusing the file. Genuinely malformed selectors (whitespace, missing model, unsupported suffix) are still errors.
- **The UI keeps the real target visible.** The roles page, model picker, and TUI role screen parse leniently, so a built-in provider shows as a target with a "not declared in models.yml" hint instead of appearing unset or unresolvable.

## Changed

- `parseRoleSelector` takes an optional `allowUnknownProvider` mode for callers that validate syntax and report the unknown provider separately.

## Security

- No new runtime dependency. No OMP `agent.db`, OAuth refresh token, or project-local `.omp` overlay is read or modified.
- Validation changes affect diagnostics only; every write still goes through the hash-guarded `previewPatch` / `commitPatch` path.

## Known Limitations

- An undeclared provider is a warning because this app cannot see extension registrations. A typo in a provider name therefore still saves; OMP reports the unresolved role at runtime.
- Installers remain unsigned; WinGet and Chocolatey remain subject to their upstream review processes.
