# OMP Switch v0.4.4

This release closes the longest-standing gap in the release notes: **update checking** is now
implemented. After v0.4.0–v0.4.3 each release's feature-status block said *Update checking: not
implemented; no update manifest is published with this release* — this release ships the manifest
and the in-app checker that consumes it.

The checker is deliberately the least invasive design that still tells the user about a new release:
it fetches a signed manifest from GitHub, verifies it against a hardcoded Ed25519 public key, and on
finding a newer release shows a top-bar badge plus a version line in the Profile drawer's new
"关于/About" tab with a link to the release page. **It never downloads or installs binaries.** This
is also the first non-user-initiated outbound network request in OMP Switch (gateway, discovery, and
OAuth are all user-clicked), so it is on by default but trivially off, silent on every failure, and
sends nothing upstream.

## Added

- **Update checking**: approximately 30s after launch (and then every 24h), if auto-check is on and
  the last successful check was ≥ 24h ago, the app GETs `latest.json` and `latest.json.sig` from the
  release's `latest` alias, verifies the Ed25519 signature against a hardcoded public key, and
  compares the release version to the running version. A newer release lights a dot badge on the
  top bar and populates the Profile drawer's new **关于** tab: current version, latest version, a
  one-line summary, a `[前往下载]` button (opens the release page), and a `[立即检查]` button that
  bypasses the throttle and the enabled flag. An auto-check toggle in the same tab turns all
  background checking off — when off, the app makes no non-user-initiated network requests at all.
- **Signed update manifest**: each release now publishes `latest.json` (version, release, url,
  summary, publishedAt) alongside `latest.json.sig`. The CI signs the manifest bytes with an
  Ed25519 private key held as a secret and re-verifies the signature against the app's hardcoded
  public key before uploading, so a key mismatch fails the release rather than shipping an
  unverifiable manifest.
- **`app:open-external` IPC**: opens an external URL through `shell.openExternal` behind a
  `github.com`-only https allowlist, so the renderer can never be coaxed into opening an arbitrary
  URL.

## Security

- This is the first non-user-initiated outbound request in OMP Switch. Its privacy posture is
  explicit: it makes exactly two GET requests to fixed GitHub URLs, carries no user identifier,
  telemetry, or query string; it sends nothing upstream.
- The manifest is **signature-verified**: every `latest.json` is checked against a hardcoded
  Ed25519 public key (`packages/core/src/update.ts`) before any field is trusted, and the signature
  is computed over the exact bytes the CDN served (not a re-serialized copy), so a CDN that rewrites
  whitespace is caught as a mismatch. A forged or tampered manifest, a network failure, a timeout,
  or a malformed payload all resolve to "no update" silently — no spurious version is ever shown.
- The auto-check toggle defaults to **on** (the feature's value is being told about a new release)
  and is trivially off. Turning it off stops the background timer immediately.
- Update checking never downloads or installs binaries; `[前往下载]` only opens the GitHub Release
  page in the user's browser. This stays inside the documented product boundary — no downloading
  unknown binaries, no cloud sync.
- No new dependencies: Ed25519 signing/verification uses Node's built-in `crypto` and the manifest
  is fetched with the built-in `fetch`.
- No existing IPC channel, secret surface, snapshot/hash-guard write path, loopback gateway, or
  filesystem surface was changed. The new code is read-only with respect to OMP config.

## Changed

- The Profile drawer gains a fifth tab, **关于**, holding the version/update panel. The other four
  tabs (设置 / 项目 / 快照 / OMP) are unchanged.
- The release workflow's `draft-release` job now generates and signs the update manifest and
  attaches `latest.json` + `latest.json.sig` to the release after creating the draft. The `dist/`
  invariant (exactly one `.exe` and one `.zip` before hashing) is unchanged; the manifest assets
  are release attachments, not build artifacts.

## Feature status

- **Update checking**: **implemented**. Ed25519-signed manifest fetched from GitHub, signature
  verified against a hardcoded key, throttled to 24h, silent on failure, auto-check on by default
  with a manual toggle. Only notifies; never auto-downloads or installs. Requires the
  `OMP_UPDATE_ED25519` repository secret to be set for the manifest to be signed; without it the
  checker finds no signed manifest and stays silent.
- **Gateway**: experimental, headless only (`--gateway [profile]`), loopback with a mandatory
  bearer token; unchanged in this release.
- **OAuth integration**: passthrough to `omp auth status` / `omp auth login` only; no token storage
  or refresh handling in-app; unchanged.
- **Session indexing**: always on — two-phase incremental refresh backed by the on-disk metadata
  cache; unchanged.

## Known limitations

- The update manifest is only signed when the `OMP_UPDATE_ED25519` repository secret is
  set. If it is absent, the workflow warns and skips the manifest assets; the release still
  publishes, but the in-app checker finds no signed manifest and silently reports nothing until a
  later release that ships one.
- The desktop application is Windows-only because its credential path uses Windows DPAPI.
- The binaries are not code-signed, so SmartScreen can warn on first run.
- Mica requires Windows 11 22H2+ and falls back to solid surfaces elsewhere; the custom title bar
  requires Windows 10+ and falls back to the system frame elsewhere.
- winget and Chocolatey submissions remain pending in their external review queues.
