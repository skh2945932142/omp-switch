# OMP Switch v0.4.0

This release reworks the interaction model and the visual finish of the desktop app. The headline
fix: collapsing a provider's model list no longer opens the right-hand drawer — expanding and
collapsing is now all the card header does, and editing moved to a hover-revealed pencil button.
The detail/editor drawer became a floating sheet that springs in over the workspace instead of
squeezing it, and the theme gained a manual light/dark/system switch alongside the OS-following
default.

`omp-switch-cli.exe`. The headless CLI image is published as
`ghcr.io/skh2945932142/omp-switch-cli:0.4.0` and `:latest`.

## Added

- **Manual theme switch**: light / dark / system in the top bar, persisted across sessions. The
  choice drives `color-scheme` (one `light-dark()` token definition serves both tracks) and is
  forwarded to the main process so the native title-bar overlay buttons flip with it.
- **Custom title bar**: the web topbar doubles as the drag region with native overlay window
  buttons (`titleBarStyle: "hidden"` + `titleBarOverlay`), reclaiming the OS caption height,
  letting Mica reach the top edge, and keeping Snap Layouts and system menus.
- **Tooltips** on top-bar icon buttons via Radix Tooltip — styled, fast, and keyboard-accessible,
  replacing slow native `title` hints.
- A browser-preview dev server (`pnpm preview:renderer`) that mirrors the electron-vite alias so
  renderer-only work no longer needs Electron.

## Changed

- **Provider cards**: clicking the header now only expands/collapses the model list (animated via
  a CSS grid-rows transition); an edit pencil appears on hover; the selected-state ring is gone —
  expansion is the focus. Model rows are display-only; quick-assign stays.
- **Detail/editor drawer → floating sheet**: it overlays the workspace with a spring animation
  instead of squeezing it as a third column, so opening it no longer reflows the page.
- **Native `<select>` replaced** by a styled Radix Select (profile picker, auth mode, discovery
  type, default thinking level, gateway upstream kind) for one consistent control language.
- **Scrollbars** are hairline-weight, theme-aware, and quiet until hovered.
- Buttons compress slightly on press; section switches crossfade with a slight rise.

## Fixed

- Collapsing a provider's model list triggered a click on the provider and opened the right-hand
  drawer; expand/collapse and select/open-drawer shared one click handler. They are now separate
  controls and can no longer fire together.

## Security

- One new IPC channel (`app:set-theme`) forwards the theme choice to the main process; it writes
  only `nativeTheme.themeSource` and crosses the sandbox boundary with a string argument.
- The hidden-title-bar change keeps the sandbox, context isolation, and navigation blockers
  unchanged; the drag region is CSS-only (`-webkit-app-region`).

## Feature status

- **Gateway**: experimental, headless only (`--gateway [profile]`), loopback with a mandatory
  bearer token; unchanged in this release.
- **OAuth integration**: passthrough to `omp auth status` / `omp auth login` only; no token
  storage or refresh handling in-app.
- **Session indexing**: always on — two-phase incremental refresh backed by the on-disk metadata
  cache; unchanged in this release.
- **Update checking**: not implemented; no update manifest is published with this release.

## Known limitations

- The desktop application is Windows-only because its credential path uses Windows DPAPI.
- The binaries are not code-signed, so SmartScreen can warn on first run.
- Mica requires Windows 11 22H2+ and falls back to solid surfaces elsewhere; the custom title bar
  requires Windows 10+ and falls back to the system frame elsewhere.
- The conflict dialog and enabledModels coverage marks are exercised on real configurations; the
  browser preview mock cannot trigger either path.
- winget and Chocolatey submissions remain pending in their external review queues.
