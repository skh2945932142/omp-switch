# OMP Switch v0.3.2

This release rebuilds the interface around two ideas: model roles become a first-class page where
you pick a provider and a model directly instead of typing selector strings, and the whole visual
language is redesigned — untinted neutrals, a single teal reserved for selection and focus,
ink/paper inversion for primary actions, and a system-following dark theme.

No changes were made to the config write path, the IPC surface, or credential handling; every
visual change lives in the renderer's CSS token layer.

## Added

- A dedicated **Roles** page: each OMP role is a row with a Chinese gloss, its resolved selector
  chain (`@default → provider/model`), capability chips, and live warnings — `@role` reference
  cycles, unparseable selectors, and `:off`/`:auto` misuse are reported in place instead of waiting
  for the diagnostics drawer. Custom roles found in `config.yml` beyond the ten documented ones are
  listed and editable instead of being silently preserved but invisible.
- A **searchable model picker**: one popover lists every model grouped by provider (name, id,
  capability chips, context window) with instant search across provider, id, and name; pinned
  special values (`@default`, `*`, clear); a segmented thinking-level control restricted to the six
  levels OMP accepts as a role suffix; and full keyboard navigation. It is shared by the Roles page
  and gateway upstream rows — replacing a native `<select>` that was unusable with large catalogs.
- **Quick-assign on model rows**: hovering a model in the provider list reveals a target action
  that assigns it to any role in one click, preserving that role's existing thinking suffix.
- **Split save semantics with dirty tracking**: roles and settings commit independently; the
  top-bar save button enables only when something is pending; pending sections show an amber dot in
  the navigation; `Ctrl+S` commits everything pending in one snapshot; switching profiles asks
  before discarding unsaved edits (switching sections keeps them — nothing is lost, so no prompt).
- A **dark theme** that follows the OS (`prefers-color-scheme`), with layered true-neutral darks
  rather than tinted ones, and a **Mica** window material on Windows 11 22H2+ (older systems and
  browser previews fall back to solid surfaces automatically).
- A **toast queue** (success auto-dismisses, errors persist longer and can be closed) replacing the
  single overwriting notice banner.

## Changed

- Visual language, end to end: untinted zinc neutrals; the teal accent is demoted to a *signal*
  color that only marks selection, focus, and switch state — primary buttons are ink/paper
  inversion; status pills became a colored dot plus quiet text; separation comes from tone and soft
  shadows instead of borders on everything.
- The left navigation is a proper source list (tonal active pill with a signal marker); provider
  cards are borderless inset groups whose model rows are separated by internal hairlines.
- All checkboxes render as switches; the thinking-level picker is a segmented control; type is
  14px Segoe UI Variable with a one-notch looser rhythm; monospace text (selectors, model ids,
  numbers) is Cascadia Mono.
- The roles editor moved out of the Profile drawer, which now holds only settings, snapshot,
  OAuth, and raw YAML.

## Fixed

- The "new provider" dropdown menu no longer stays open when clicking elsewhere (replaced with a
  keyboard-accessible menu that closes on outside click and Escape).

## Security

- No new IPC channels; the renderer remains sandboxed with `contextIsolation`. The three new UI
  dependencies (`@radix-ui/react-popover`, `@radix-ui/react-dropdown-menu`, `sonner`) are
  client-side-only and fetch nothing.
- The Mica path runs `executeJavaScript` from the main process to add one CSS class; it grants the
  renderer no new capabilities.

## Feature status

- **Gateway**: experimental, headless only (`--gateway [profile]`), loopback with a mandatory
  bearer token; upstream model selection now uses the searchable picker, the relay itself is
  unchanged.
- **OAuth integration**: passthrough to `omp auth status` / `omp auth login` only; no token storage
  or refresh handling in-app.
- **Session indexing**: always on — two-phase incremental refresh backed by the on-disk metadata
  cache; unchanged in this release.
- **Update checking**: not implemented; no update manifest is published with this release.

## Known limitations

- The desktop application is Windows-only because its credential path uses Windows DPAPI.
- The binaries are not code-signed, so SmartScreen can warn on first run.
- The theme follows the OS with no in-app light/dark toggle yet; Mica requires Windows 11 22H2+
  and falls back to solid surfaces elsewhere.
- Session cost figures come from OMP-recorded costs; sessions without a recorded cost show $0.00
  unless local prices are entered as a cross-check.
- winget and Chocolatey submissions remain pending in their external review queues.
