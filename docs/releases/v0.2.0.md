# OMP Switch v0.2.0

First tagged release. OMP Switch manages [Oh My Pi](https://github.com/can1357/oh-my-pi) model-provider
configuration by editing files you own and it does not: `~/.omp/agent/models.yml` and `config.yml`.

Verified against Oh My Pi **17.3.7**. Schema majors **16 and 17** are writable; anything else opens
read-only rather than being migrated on a guess.

## Downloads

| `OMP-Switch-Setup-0.2.0.exe` | Windows x64 | NSIS installer, **per-user** |
| `OMP-Switch-0.2.0-win.zip` | Windows x64 | Portable, unzip and run |
| `SHA256SUMS.txt` | — | Verify before running |

Also installable with Scoop (`scoop bucket add omp-switch https://github.com/skh2945932142/omp-switch`)
and as a Docker image for the headless CLI (`ghcr.io/skh2945932142/omp-switch-cli:0.2.0`). winget and
Chocolatey manifests are prepared but not yet submitted. See [docs/install.md](../install.md).

Installs are per user by design: the credential vault is encrypted with the installing Windows
account's DPAPI key, so a per-machine install would create a vault the other accounts cannot read.

### Verify what you downloaded

```powershell
(Get-FileHash -Algorithm SHA256 ".\OMP-Switch-Setup-0.2.0.exe").Hash.ToLower()
# compare against SHA256SUMS.txt
gh attestation verify ".\OMP-Switch-Setup-0.2.0.exe" --repo skh2945932142/omp-switch
```

The binaries are **not code-signed**, so SmartScreen will warn on first run. The build-provenance
attestation is the current substitute; verify it rather than trusting the file blindly.

## What it does

- **Providers and models** — 54 versioned presets, six discovery modes (Ollama, llama.cpp, LM Studio,
  OpenAI models-list, proxy, LiteLLM), and editing for provider, model, `modelOverrides`, `compat`,
  `remoteCompaction`, `cost` and transport fields.
- **Roles and selection** — all ten Oh My Pi roles, `modelProviderOrder`, `enabledModels`,
  `disabledProviders` (including path-scoped entries), and `defaultThinkingLevel`.
- **Profiles** — the default profile plus named profiles, following Oh My Pi's own path overrides.
- **Safe writes** — hash-guarded against external edits, atomic temp-file writes, a snapshot before
  every commit, and a guarded restore.
- **Credentials** — API keys are encrypted with Windows DPAPI and referenced from config by command;
  they never appear in Oh My Pi configuration.
- **Prompts, skills and sessions** — managed, with session content read on demand only.
- **Usage dashboard** — spend, requests, tokens, cache and reasoning totals, a per-day trend, and
  breakdowns by model and provider, with local per-model prices for cross-checking.
- **Loopback gateway** — `/healthz`, `/v1/models`, chat and responses, with failover before any bytes
  are relayed, a mandatory bearer token, `Host` validation and cross-origin refusal.
- **JSON CLI** — a stable `{version, ok, data | error}` envelope, on Windows through the packaged app
  and on any platform through the Electron-free headless build.

## Correctness fixes worth calling out

These were found by checking the code against the real Oh My Pi, not against assumptions:

- **Every installation with Oh My Pi present was silently read-only.** `omp --version` prints
  `omp/17.3.7`, and the version parser required the number at the start of the line or after
  whitespace, so `/` did not match, the version classified as unrecognized, and writes were blocked.
- **Thinking levels are three different sets.** `defaultThinkingLevel` excludes `off`; a role suffix
  excludes both `off` and `auto`. Only documented level names are stripped as a suffix, so a
  colon-bearing model id such as `ollama/llama3.1:8b` still resolves.
- **Override-only providers were not validated.** A provider with no `models` must carry one of
  `baseUrl`/`apiKey`/`headers`/`compat`/`disableStrictTools`/`modelOverrides`/`discovery`/
  `remoteCompaction` or `auth: none`. Writing one without any of those makes Oh My Pi reject the whole
  document and fall back to its built-in catalog, dropping every custom provider.
- **Oh My Pi's own path overrides are honored** — `PI_CONFIG_DIR`, `OMP_PROFILE`, `PI_PROFILE`,
  `PI_CODING_AGENT_DIR`. Without them, edits were written to files Oh My Pi never reads and reported
  as success.
- **Project overlay discovery stopped nowhere.** It walked past the project and reported the
  user-level `~/.omp` as a project overlay; it now stops at the home boundary.
- **Session usage was never read.** The indexer looked for `usage`, `cost`, `model` and `provider` at
  the top level of a session JSONL line; Oh My Pi writes all of them on `message`, with cost nested at
  `message.usage.cost.total`. Failures come from `message.stopReason`, not from `type`, which is
  always `"message"`.

## Security

- The gateway requires a bearer token (`userData/gateway/gateway.token`, mode `0600`), rejects
  non-loopback `Host` headers with 421 and any request carrying `Origin` with 403, relays only an
  allowlist of response headers, and times out upstream requests. Binding to `127.0.0.1` is not
  treated as access control: a local process or a web page could otherwise spend your credits.
- A plaintext-looking `apiKey` in `models.yml` is reported by the core validator, so the JSON CLI is
  covered too, and keys written by hand are also flagged.
- `restoreSnapshot` refuses to overwrite a file edited after the snapshot was taken.
- Deleting an anchored YAML node, or rewriting an alias, is refused rather than producing a file with
  dangling aliases. Editing an anchored node in place is allowed and preserves the anchor.
- The secret bridge publishes as Native AOT because Oh My Pi runs an `!command` key reference with a
  hard 10 second timeout and **silently omits the key** on failure. Cold start is 29 ms median.

Full detail in [docs/security.md](../security.md).

## Known limitations

- **Windows only for the desktop app.** The credential path is DPAPI plus a `net10.0-windows` bridge.
  The headless CLI runs anywhere Node 24 does but cannot open the vault. Linux desktop packages are
  deliberately absent until a credential backend is chosen; the blockers are listed in
  [docs/install.md](../install.md#linux-support).
- **Not code-signed.** SmartScreen will warn.
- No cloud sync, tray switching, automatic account rotation, or signed in-app updates.
- The gateway records latency and failures passively from real traffic; there is no active health
  probe or circuit breaker.
- A clean-Windows install, upgrade and uninstall regression has not been performed on this release.
