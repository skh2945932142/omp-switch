# OMP Switch v0.3.1

This release rebuilds session indexing around one cached summary per primary session file, so the
Sessions page appears in tens of milliseconds, refreshes touch only what changed, and ancillary
per-session data is never parsed. It also hardens the renderer boundary: absolute paths and byte
offsets no longer cross the Electron bridge, and several unused native capabilities were removed.

Verified on a real archive before release: 32 primary sessions (81 MB) discovered in 44 ms with
titles visible immediately, 75 ancillary JSONL files (37 MB) skipped entirely, steady-state
refreshes reusing every cache with zero bytes scanned, and usage totals matching the previous
event-level index exactly (5,528 requests, $402.22 recorded cost).

## Added

- The Sessions page lists one entry per primary OMP session — title, latest model, provider, and
  status, message and request counts, failures, aggregated tokens and cost — with paging and a
  refresh-statistics line (discovered / skipped / reused / changed / rebuilt / bytes scanned /
  invalid lines / errors).
- Empty states distinguish a missing sessions directory, an unrecognized layout, initial indexing,
  and partially unreadable files.
- The session detail view pages through history: 50 messages per page, newest first, 4 KiB text
  previews, with an explicit "load earlier" continuation.
- An explicit "rebuild index" action forces a full re-index; ordinary refresh stays incremental.

## Changed

- Session scanning is bounded to the verified OMP primary-session naming at the sessions root and
  inside one-level project group directories. Ancillary per-session directories are no longer
  parsed; unrecognized layouts produce a visible diagnostic instead of a broad recursive scan.
- Refresh is two-phase: quick discovery (stat + head hash + first chunk) yields a usable list
  immediately, while full aggregation streams in the background with at most two concurrent file
  readers. Concurrent refreshes for the same profile are coalesced into one task.
- Per-file incremental cache: unchanged files are reused without reads, appended files are parsed
  tail-only, and a shrink or head change rebuilds that file alone. Failed reads keep the previous
  cache, marked stale — a missing or temporarily unreadable sessions root never wipes the list.
- Usage accounting consumes compressed per session/day/provider/model records; per-model,
  per-provider, and per-day reports are unchanged in accuracy.
- Metadata persistence: sqlite stores session summaries and usage in `session_cache`/
  `session_usage`, applied as a transactional per-file diff; the legacy event-level
  `session_index` table is a rebuildable cache and is dropped on upgrade. The JSON fallback
  upgrades to schema v3 and writes atomically (temp file + rename).

## Security

- The renderer no longer receives absolute session file paths or byte offsets. List and message
  cursors are opaque, HMAC-signed, and bound to the file's fingerprint (size, mtime, head hash);
  replaying a cursor against a changed file is rejected.
- Message reads re-validate, before and after reading, that the resolved file still lives inside
  the current profile's sessions root, still matches the primary-session naming, and still matches
  the indexed fingerprint.
- Removed the unused `app:open-folder` IPC channel, which passed a renderer-supplied path to
  `shell.openPath`.
- The packaged build always loads the local renderer; `ELECTRON_RENDERER_URL` is honored only when
  unpackaged and must be a loopback http URL. Navigation to other origins and `window.open` are
  denied.

## Feature status

- **Gateway**: experimental, headless only (`--gateway [profile]`), loopback with a mandatory
  bearer token; unchanged in this release.
- **OAuth integration**: passthrough to `omp auth status` / `omp auth login` only; no token
  storage or refresh handling in-app.
- **Session indexing**: always on — two-phase incremental refresh backed by the on-disk metadata
  cache; "rebuild index" forces a full re-scan.
- **Update checking**: not implemented; no update manifest is published with this release.

## Known limitations

- The desktop application is Windows-only because its credential path uses Windows DPAPI.
- The binaries are not code-signed, so SmartScreen can warn on first run.
- Session layouts outside the verified primary-session naming are reported rather than scanned.
- Message previews are capped at 4 KiB per message.
- Session cost figures come from OMP-recorded costs; sessions without a recorded cost show $0.00
  unless local prices are entered as a cross-check.
- winget and Chocolatey submissions remain pending in their external review queues.
