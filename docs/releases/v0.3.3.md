# OMP Switch v0.3.3

This release makes the app's safety model visible and its daily operation faster. Every save now
shows a line-level diff of exactly what will be written before anything touches disk, snapshots
become a browsable timeline, and a command palette plus section shortcuts cut mouse travel. It
also hardens validation against two real-world failure modes found while diagnosing a
"roles saved but OMP ignores them" report: explicitly null object fields and dev-session
credential references, both of which make OMP silently drop every custom provider.

## Added

- **Two-step saves with a diff preview**: saving roles, settings, providers, or deleting a
  provider first opens a review dialog showing the exact text `models.yml` and `config.yml` would
  receive — line-level additions and deletions with collapsed context and per-file change counts.
  The preview is produced by a new `previewPatch` core path that runs the identical plan→YAML
  pipeline with no filesystem effects; the commit re-validates and re-guards on confirmation, so
  an external edit landing between preview and confirm still fails safely.
- **Snapshot timeline**: the Profile drawer lists every retained snapshot (up to 30 per profile)
  with timestamps, and any entry can be restored. Restore keeps the existing guard against
  overwriting external edits.
- **Conflict-resolution dialog**: when the hash guard detects an external edit, a dialog explains
  what happened and offers a one-click reload, replacing a raw error toast.
- **Command palette** (`Ctrl+K`): jump to any section, switch profiles, jump to a provider, or
  run frequent actions (new provider, save all, create snapshot, reload).
- **Keyboard shortcuts**: `Ctrl+1`…`Ctrl+7` switch sections, `?` opens the shortcut reference,
  alongside the existing `Ctrl+S`.
- **enabledModels coverage signals**: provider cards show an "未启用 / 启用 N/M" chip when the
  configured rules do not fully cover a provider, the role picker marks models the OMP catalog
  will filter out, and the roles page warns when an assigned model is filtered. A role pointing
  at a filtered model is exactly the "saved but ignored" failure this guards against.
- Success toasts now name the file that was written.
- Loading skeletons for the sessions and usage pages; usage gains 7/30-day/90-day/all range
  presets as a segmented control.

## Changed

- All `window.confirm` prompts (discard guard, legacy migration, provider deletion) are replaced
  by in-app dialogs that match the theme.
- `prefers-reduced-motion` is respected globally — users who ask for reduced motion get none.

## Fixed

- Validation no longer lets an explicitly `null` `headers`, `compat`, or `modelOverrides` pass:
  OMP's schema is all-or-nothing and rejects the whole `models.yml` for them, silently disabling
  every custom provider. These now surface as errors on load (`headers` previously slipped past
  a falsy check; `compat` and `modelOverrides` were unchecked).
- An `apiKey` command reference pointing into `node_modules` or passing a relative `"."` app
  argument now warns (`provider.apiKey-fragile-command`): such references only work inside the
  dev checkout that wrote them, and OMP silently drops the key — and the provider — when run
  from any other directory.

## Security

- Two new IPC channels (`omp:preview`, `omp:list-snapshots`) are read-only views over existing
  adapter and metadata-store methods; no new capability crosses the sandbox boundary.
- `previewPatch` performs no filesystem writes, snapshot creation, or vault access.

## Feature status

- **Gateway**: experimental, headless only (`--gateway [profile]`), loopback with a mandatory
  bearer token; unchanged in this release.
- **OAuth integration**: passthrough to `omp auth status` / `omp auth login` only; no token
  storage or refresh handling in-app.
- **Session indexing**: always on — two-phase incremental refresh backed by the on-disk metadata
  cache; unchanged in this release.
- **Update checking**: not implemented; no update manifest is published with this release.

## Known limitations

- The desktop application is Windows-only because its credential path uses Windows DPAPI.
- The binaries are not code-signed, so SmartScreen can warn on first run.
- The theme follows the OS with no in-app light/dark toggle yet; Mica requires Windows 11 22H2+
  and falls back to solid surfaces elsewhere.
- The conflict dialog and enabledModels coverage marks are exercised on real configurations; the
  browser preview mock cannot trigger either path.
- winget and Chocolatey submissions remain pending in their external review queues.
